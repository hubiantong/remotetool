## Context

从零构建一个私密、轻量、跨 **Windows / Linux(Ubuntu) / Android** 的远程工具，包含三大功能：**远程终端、文件传输、端口转发**（「端口调用」按 SSH 隧道语义理解）。安卓端定位为主控端 + 文件传输对端，不要求充当终端/端口转发的服务端。

参考价值：`D:\project\uu` 的四份逆向报告已提炼出 UU 远程的精华设计——**TERM 终端帧协议**（16字节头：type+sessionId+payloadLen，ConPTY/PTY 后端）、**文件传输状态机**（Ask→Confirm→Block+ACK→Complete，分块/续传/校验）、**8位协助码配对**。UU 基于 WebRTC（重、依赖厂商信令，不私密）；我们只有这三个功能、不需要屏幕串流，可用更轻的 **QUIC** 方案替代，配对/信令/中继全部自持。

**因未收到选择确认，采用以下默认假设（可在实施中随时调整）**：网络=局域网直连优先+自建中继可扩展；技术栈=**Go**；UI=**Web界面+CLI**（安卓后续用薄壳App内嵌）；首期=终端+文件先行。

## 技术方案

**架构**：每台设备一个守护进程 `rtd`（单一静态二进制）+ CLI `rt` + 内置 Web UI。
- **传输层**：QUIC（quic-go）单 UDP 连接承载一切，每条逻辑通道一个 QUIC stream，天然多路复用、无队头阻塞；传输层抽象接口，保留 TCP+TLS+smux 兜底（安卓适配万一受阻时切换）。
- **身份与加密（端到端）**：设备 = Ed25519 密钥对，设备ID=公钥指纹；QUIC 内建 TLS1.3，对端证书按设备ID 钉扎（pin）。首次配对用 **6位配对码 + SPAKE2** 防中间人（借鉴 UU 协助码模式，去中心化）。中继只见密文。
- **发现**：局域网 mDNS 直连；广域网经自建 `hub`（注册/信令/密文中继，二期实现，架构预留）。
- **通道协议**：控制流（JSON 信令）+ 数据流（终端/文件/转发），帧格式借鉴 UU 的 TERM 设计。
- **终端服务端**（Win/Linux）：Windows 用 ConPTY（CreatePseudoConsole，参考 UU conpty_bridge），Linux 用 fork/exec+PTY；多会话、resize、断线重连后会话存活。
- **文件传输**：分块（1-4MB）+ 流水线 ACK + 断点续传（checkpoint 落盘）+ SHA-256 校验 + 冲突策略（重命名/跳过/覆盖）+ 递归目录 + 浏览操作（list/mkdir/rename/delete，供文件管理器）。
- **端口转发**：`-L` 本地转发（客户端监听→远端拨目标）、`-R` 远程转发，CLI + Web 管理表；SOCKS5 列为后续。
- **Web UI**：Go embed 内嵌进二进制；Vite+TS+xterm.js，依赖极简；页面：设备/配对、终端、文件管理（双栏+拖拽+进度）、端口转发、设置。仅监听 127.0.0.1+token。
- **CLI**：`rt serve / pair / ls / term <设备> / cp <src> <dst> / fwd [-R] ...`。

## 实施阶段

1. **Stage 0 基础**：go module、目录骨架、配置/日志、身份模块（密钥、设备ID、SPAKE2 配对码）、构建脚本（windows/amd64、linux/amd64+arm64 交叉编译）。
2. **Stage 1 连接**：QUIC 传输层 + mDNS 发现 + 配对流程 + 会话/通道多路复用；`rt ls` 能看到并连接已配对设备。*验证：本机跑两个 daemon 实例（不同端口/配置目录）完成配对连通。*
3. **Stage 2 终端**：TERM 帧协议 + ConPTY 后端（Windows）+ PTY（Linux 源码就绪）+ Web 端 xterm.js + `rt term`。*验证：本机双实例互开终端执行命令、resize、断开重连。*
4. **Stage 3 文件传输**：传输引擎（分块/ACK/续传/校验/冲突策略）+ Web 文件管理器 + `rt cp`。
5. **Stage 4 端口转发**：-L/-R + CLI + Web 管理页。
6. **Stage 5 hub 与广域网**：自建 hub（信令+密文中继）+ hub 配置接入；附部署文档。
7. **后续（不在本次）**：安卓 APK 薄壳（Kotlin+WebView+前台服务托管 rtd）、SOCKS5、UDP 打洞直连、Linux 实机验证。

## 验证方式

- 每个 Stage 用本机双实例（模拟两台设备）做端到端手工验证 + Go 单元测试（帧编解码、传输引擎断点续传、配对码交换）。
- 交叉编译产出三平台二进制并冒烟（--version、本地 serve）。
- 最终演示：Windows 主机经 Web UI 对第二实例完成 终端执行命令 / 传输含中文的大文件并中断续传 / 转发一个端口访问对端服务。
